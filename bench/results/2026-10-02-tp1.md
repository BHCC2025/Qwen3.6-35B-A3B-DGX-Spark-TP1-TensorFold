# TP1 benchmark, 2026-10-02

Raw output, one set per run: `2026-10-02-<label>.log` (`bench/bench.sh`, the kit's shared suite),
`2026-10-02-<label>-concurrent.json` (TensorFold's `tools/bench_concurrent.py`, run by `bench.sh` with
`CONCURRENT=1,8`) and `2026-10-02-<label>-mem.txt` (memory samples while the server ran). Labels: `tp1` (the default),
`tp1-p1` (`PARALLEL=1`, TensorFold's own default of one request at a time), `tp1-64gb` (the 64 GB profile on a
simulated 64 GB Spark).

TensorFold sized the default window at startup to 237,329 tokens per stream for 8 streams (estimate 88.73 GiB within

numbers matched the `tp1` run's, but its smoke test used the kit's checks with thinking on, which this model fails (see

## Memory

Sampled every ~4 s (a 2 s sleep plus the sampling) for the whole life of the server: MemAvailable, system-wide use
(MemTotal − MemAvailable), the server's memory as `nvidia-smi` reports it, and the container's cgroup. After
`bench.sh`, each run also sent concurrent unique prompts of ~63K tokens (Python standard-library source, 32 reply
tokens) to fill every stream's cache close to the 65,536-token window: 8 at once in `tp1`, 4 in `tp1-64gb`. Other
work on the Spark moved the baseline by a few GiB between runs, so "server" below is the change from just before start.

| Run | Startup estimate | Used before start | Loaded, idle | Peak, system-wide | Server at peak (system-wide) | Server at peak (`nvidia-smi`) |
|---|---:|---:|---:|---:|---:|---:|
| `tp1` + 8 × ~63K | 88.73 GiB | 20.9 GiB | 43.2 GiB | 54.8 GiB | **33.9 GiB** | 33.4 GiB |
| `tp1-p1` (no fill) | 42.60 GiB | 18.5 GiB | 38.9 GiB | 46.2 GiB | 27.7 GiB | 23.1 GiB |
| `tp1-64gb` + 4 × ~63K | 34.67 GiB | (simulated) | | | **38.1 GiB** | 27.8 GiB |

The weights take 19.5 GiB (`nvidia-smi` at idle). TensorFold's estimate is what every stream would take filled to
its window plus three kept prompt states; the caches fill into it as contexts grow, so the default profile's 88.7 GiB
can only be reached on a 128 GB Spark.

### The simulated 64 GB Spark

We have no 64 GB Spark. A 64 GB one has about 57.5 GiB of MemTotal (ours shows 121.7 GiB of 128) and a clean
headless DGX OS uses about 4 GiB, so the run left 53.5 GiB available: a root process locked the rest of memory with
`mlock` (55.2 GiB; locked pages cannot be swapped or reclaimed) before the server started, and the container was given
`TENSORFOLD_MEMORY_RESERVE_GIB=5.8`, the reserve TensorFold computes on a 57.5 GiB machine (a tenth of memory; on
ours it would be 12.2 GiB). TensorFold's startup budget came out at 47.44 GiB.

- At start 52.8 GiB was available; the server loaded (estimate 34.67 GiB within 47.44 GiB), passed the whole bench
  and took four ~63K-token prompts at once.
- The lowest MemAvailable over the run was **14.8 GiB**: at its peak the server used 38.1 GiB of the 52.8.
- So on a 64 GB Spark the 64 GB profile leaves about 15 GiB of headroom for the OS and anything else, with every
  stream nearly full. The default profile would not: by TensorFold's estimate 8 streams at `CONTEXT=auto` take the
  whole 47 GiB budget (it would size the window down to fit, leaving the OS only TensorFold's 5.8 GiB reserve).
- Other settings within the 64 GB budget, by TensorFold's startup estimate (not benched): `PARALLEL=8 CONTEXT=32768`
  31.76 GiB, `PARALLEL=1 CONTEXT=131072` 32.10 GiB, `PARALLEL=8 CONTEXT=65536` 40.89 GiB, `PARALLEL=2 CONTEXT=131072`
  41.38 GiB, `PARALLEL=1 CONTEXT=262144` 42.60 GiB.

Speed is the same as on 128 GB (the hog takes memory, not bandwidth); the lower 8-user totals are `PARALLEL=4`.

## Notes

- **Thinking and the smoke test.** The kit's smoke test asks its arithmetic, fact and code questions with the server's
  default (thinking on) and 256-400 reply tokens. Qwen3.6-35B-A3B thinks longer than that, so in the first start's run
  arithmetic and code came back with an empty `content` and the reasoning cut off. The runs above sent those three
  with `enable_thinking: false` (the thinking check unchanged); `scripts/smoke-test.sh` now does the same through the
  kit's `SMOKE_NO_THINK=1` (kit 0.5.1), and passed again against a live server after the kit update.
- **Prefix reuse.** TensorFold keeps prompt states, so run 2 of the ~9.3K-prompt cell (same prompt) is a cache hit
  (TTFT 0.05 s). Use the cold-prefill rows, which send a unique prompt each time. That cell's reply is 71 tokens.
- **Sampling.** `bench.sh` sets no temperature, so its decode cells use the model's default (temperature 1.0,
  top_k 20, top_p 0.95). The concurrency cells are greedy (`--temperatures 0`), so every reply can be compared by
  token hash with the same request alone.
- TensorFold's model list (`GET v1/models`) reports no `max_model_len`, so the logs show `max_model_len=0`. The needle
  test (`LONG=1`) was not run: it sizes prompts with vLLM's `/tokenize` endpoint, which TensorFold does not serve.
